# CardDemo Dependency Map

Program-to-program edges were re-extracted directly from the COBOL sources (`CALL 'literal'`, `EXEC CICS XCTL PROGRAM(...)`, `EXEC CICS LINK PROGRAM(...)`); dataset lineage was parsed from the `//name EXEC` / `//name DD` cards and the in-stream IDCAMS control statements of every JCL member. Nothing here is inferred from documentation.

Sources: `app/cbl/`, `app/app-authorization-ims-db2-mq/cbl/`, `app/app-transaction-type-db2/cbl/`, `app/app-vsam-mq/cbl/`, `app/jcl/`, `app/proc/`, extension `jcl/` directories, `app/catlg/LISTCAT.txt`.

## 1. How the edges were resolved

| Edge kind | Source construct | Resolution |
| --- | --- | --- |
| `XCTL` | `EXEC CICS XCTL PROGRAM('COMEN01C')` | literal, exact |
| `LINK` | `EXEC CICS LINK PROGRAM(WS-PGM-AUTH-FRAUD)` | the data name is a `PIC X(08) VALUE 'COPAUS2C'` constant, so the target is static |
| `XCTL-VAR` | `EXEC CICS XCTL PROGRAM(CDEMO-TO-PROGRAM)` | resolved from every `MOVE <literal-or-constant> TO CDEMO-TO-PROGRAM` in the same program |
| `XCTL-TABLE` | `EXEC CICS XCTL PROGRAM(CDEMO-MENU-OPT-PGMNAME(...))` | resolved from the menu option tables `app/cpy/COMEN02Y.cpy` and `app/cpy/COADM02Y.cpy` |
| `XCTL-RETURN` | `MOVE CDEMO-FROM-PROGRAM TO CDEMO-TO-PROGRAM` then `XCTL` | returns to whichever program invoked the screen; the target is only known at run time |
| `CALL` | `CALL 'CSUTLDTC'` | static COBOL call |

## 4. Dataset lineage

Every DD card carrying a real dataset name, per job step. Housekeeping DDs (`SYSPRINT`, `SYSOUT`, `SYSUDUMP`, `STEPLIB`, ...) and in-stream control-card DDs are omitted. For IDCAMS steps the direction comes from the `REPRO INFILE/OUTFILE` control statement rather than from `DISP`, because both clusters are normally allocated `DISP=SHR`. For steps that run an application program the role is the COBOL `OPEN` mode of the matching `SELECT ... ASSIGN TO <dd>` (`INPUT` -> read, `OUTPUT` -> write, `I-O` -> read/update); `CBSTM03A` inherits the modes of the files opened by its subroutine `CBSTM03B`. `&HLQ`/`&LBNM` are unresolved JCL symbols.

### Close-Process-Open VSAM pattern

The core clusters are open to CICS while the region is up, so a batch job that rewrites them must first take them out of the region:

1. `app/jcl/CLOSEFIL.jcl` runs a single `SDSF` step whose in-stream commands are `/F CICSAWSA,'CEMT SET FIL(TRANSACT|CCXREF|ACCTDAT|CXACAIX|USRSEC ) CLO'`.

2. The batch chain runs (`COMBTRAN` -> `POSTTRAN` -> `INTCALC` -> `CREASTMT`, or a reload job such as `ACCTFILE`).

3. `app/jcl/OPENFIL.jcl` issues the matching `... OPE` commands and CICS resumes serving the files.

`CARDFILE`, `CUSTFILE` and `TRANFILE` embed their own close (`CLCIFIL`) and open (`OPCIFIL`) steps around their reload steps, so reloading those three clusters is self-contained and does not need `CLOSEFIL`/`OPENFIL`.
