# CardDemo Application Inventory

> Source: `codev-workshops/uc-legacy-modernization-cobol-to-java` (AWS CardDemo mainframe credit-card application). Generated by static analysis of every COBOL program, copybook, BMS map, JCL member, PROC, CSD, DDL/DCL, IMS DBD/PSB and scheduler definition in `app/` and `samples/`. LOC = non-blank, non-comment source lines (columns 8-72). Cyclomatic complexity is approximated as 1 + IF + WHEN (excluding OTHER) + UNTIL + AND/OR.

## 8. Inventory Observations

- **Orphan / unreferenced programs**: CBTRN01C (no CSD transaction, no JCL step, no caller).
- **Missing program**: `COCRDSEC` is defined in CSD as transaction `CDV1` but has no source.
- **Unused copybooks**: `UNUSED1Y` (by name), `CSDB2RPY`/`CSDB2RWY` not COPYed by name by any scanned program.
- **Duplicate layouts**: `CUSTREC` duplicates `CVCUS01Y` (only the DOB field name differs); `COSTM01` re-keys `CVTRA05Y` by card number.
- **Spelling carried into data names**: `ACCT-EXPIRAION-DATE`, `CARD-EXPIRAION-DATE`, `MERCHANT-CATAGORY-CODE` - preserve or map explicitly during conversion.
- **Hard-coded values in JCL**: run date PARM `2022071800` (INTCALC), report date range in TRANREPT SYMNAMES, FTP host/credentials in `FTPJCL.JCL`, user passwords in `DUSRSECJ.jcl`.
- **Optional modules** are self-contained (own CSD group, JCL, copybooks) and share core VSAM files (ACCTDAT, CUSTDAT, CCXREF/CXACAIX) and the COMMAREA.
